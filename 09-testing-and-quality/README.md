6. `06-routing-and-guard-testing` - route behavior and access decisions.
7. `07-rxjs-and-async-testing` - observable flows, async behavior, cleanup.
8. `08-e2e-testing-with-playwright` - browser-level workflows.
9. `09-quality-and-ci` - linting, coverage, accessibility, CI quality gates.
10. `projects/payment-review-console` - runnable Angular application with unit tests and Playwright e2e examples.

## Runnable project setup

Generate a standalone Angular workspace with your installed CLI:

```bash
ng new payment-review-console --standalone --routing --style=css
cd payment-review-console
```

Replace its `src` folder with `projects/payment-review-console/src`. Copy `playwright.config.ts` and the `e2e/` folder into the workspace root. Keep the generated Angular workspace configuration and add the scripts and dev dependencies described in the project README.

Install dependencies and run:

```bash
npm install
ng serve
```

Run unit tests using the test runner configured by your Angular CLI version:

```bash
ng test
```

The project README includes Playwright installation, browser setup, and e2e commands.

## Test pyramid

- Unit tests: pure functions, services, reducers, component logic.
- Integration tests: component + service + router + HTTP interactions.
- End-to-end tests: critical user journeys in a real browser.
- Non-functional checks: accessibility, performance, security, and reliability.

## Important

Use the test runner generated by your selected Angular CLI version. Angular CLI defaults and test-runner integrations can vary by Angular major release. This package includes a Jasmine/Karma-style unit test example and a Playwright e2e example; adapt configuration to your chosen workspace rather than blindly replacing its generated setup.
