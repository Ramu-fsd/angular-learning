# Admin Portal Micro Frontend

**Author:** Ramu Boya  
**Portfolio:** [GitHub](https://github.com/Ramu-fsd) · [LinkedIn](https://www.linkedin.com/in/ramuboya)

An Angular 20 standalone micro frontend demonstrating an enterprise banking administration console. It is designed to be integrated as the `admin` remote in the Banking Micro Frontend platform.

## Features
- Administration overview with platform and access metrics
- Synthetic user directory with search and activate/suspend interactions
- Role and permission matrix
- Maker-checker access request queue with approve/reject simulation
- Audit trail with client-side filtering
- Platform feature-control toggles
- Angular Signals and typed TypeScript models
- Responsive layout

## Technology
- Angular 20, standalone components and built-in control flow
- TypeScript, Signals and computed state
- Native Federation integration (generated by Angular Architects CLI)

## Create the Angular workspace
From the parent `banking-micro-frontend` folder:

```bash
ng new admin-mfe --standalone --routing --style=css
```

Copy this ZIP's `src` folder over the generated `src` folder, and copy this README and `docs` folder into the project root. Then:

```bash
cd admin-mfe
npm install
ng add @angular-architects/native-federation-v4
```

Choose **Remote**, remote name **admin**, and port **4204**. Keep the federation configuration generated by the CLI. Do not replace the generated federation configuration with guessed configuration from another Angular version.

Run and build:

```bash
ng serve --open --port 4204
ng build
```

## Integration
The Banking Shell should load the remote named `admin` using the remote entry URL generated by Native Federation. Configure the host's federation manifest to point to the local remote entry on port `4204`, using the exact entry filename and exposed module generated by your installed Native Federation version.

## Demo data and security
All users, roles, requests, audit events, and metrics are synthetic. Interactions update in-memory Angular Signals only. This is not an IAM implementation and does not call a backend. Production use requires server-side authorization, least-privilege policies, immutable audit storage, approval segregation, CSRF/session protections, and API-side validation.
