# Digital Banking Customer Portal

**Author:** Ramu Boya  
**GitHub:** https://github.com/Ramu-fsd  
**LinkedIn:** https://www.linkedin.com/in/ramuboya

A portfolio-grade Angular starter for a retail digital banking portal. It demonstrates feature-based organization, standalone routing, Signals-based UI state, typed models, reactive forms, API service boundaries, responsive layouts, and test examples.

## Business capabilities

- Customer dashboard and account summary
- Account list and masked account identifiers
- Transaction history with search and category filtering
- Beneficiary management with add-beneficiary form
- Service request submission
- API integration boundary and error-handling example
- Authentication/authorization integration guidance
- Accessibility and security considerations

## Workspace setup

Use your locally installed Angular CLI so the project matches your environment:

```bash
ng new digital-banking-portal --standalone --routing --style=css
cd digital-banking-portal
```

Replace the generated `src` folder with the `src` folder in this package. Copy `docs/`, `api-contracts/`, and `testing-notes/` to the project root.

```bash
npm install
ng serve --open
```

Production build:

```bash
ng build
```

## Suggested environment configuration

Configure the API base URL using Angular environment files generated by your CLI. Do not commit secrets. For local development, use a proxy configuration to route `/api` to your Spring Boot backend.

## Backend integration

The Angular app currently uses in-memory demo data through `BankingDataService`. Replace the demo implementation with `HttpClient` calls to the API contracts in `api-contracts/openapi-outline.md`. Keep backend authorization, balance calculation, beneficiary validation, and transaction rules authoritative.

## Validation checklist

- Dashboard route loads.
- Account list shows masked account identifiers.
- Transaction search and category filter work.
- Add-beneficiary form validates required fields and account number length.
- Service request form validates required fields.
- Demo actions update local state and display feedback.
- `ng build` completes successfully.
- Keyboard navigation and mobile layout are checked.

## Important security boundary

This is a learning application. It does not authenticate users or connect to a real bank. Route guards and UI role checks are not security controls. A production deployment must use an approved OIDC Authorization Code + PKCE flow, backend authorization on every API, secure session/token handling, CSRF protection where applicable, audit logging, rate limits, fraud controls, and regulatory review. Never use real customer data in this demo.
