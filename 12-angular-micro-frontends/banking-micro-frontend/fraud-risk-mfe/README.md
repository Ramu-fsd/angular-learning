# Fraud & Risk Micro Frontend

**Author:** Ramu Boya  
**GitHub:** https://github.com/Ramu-fsd  
**LinkedIn:** https://www.linkedin.com/in/ramuboya

An Angular 20 standalone remote for a banking fraud operations platform. It is designed to be integrated into the Banking Micro Frontend shell as the `fraud-risk` remote.

## Features
- Fraud operations dashboard with synthetic KPIs
- Investigation queue with search, risk and status filters
- Case detail panel with local status transitions
- Alert feed and create-case interaction placeholder
- Detection rule catalogue with enable/disable controls
- Risk severity distribution
- Angular Signals, computed state, typed models and responsive layout

## Technology
- Angular 20 standalone components and built-in control flow
- TypeScript and Angular Signals
- Native Federation, configured by the Angular Architects CLI

## Create the app
From the `banking-micro-frontend` parent directory:

```bash
ng new fraud-risk-mfe --standalone --routing --style=css
```

Replace the generated `src` folder with this ZIP's `src` folder. Copy this README and `docs` into the project root. Then:

```bash
cd fraud-risk-mfe
npm install
ng add @angular-architects/native-federation-v4
```

Choose **Remote**, remote name **fraud-risk**, port **4205**. Keep the federation configuration generated by your installed CLI/package version.

Run and build:

```bash
ng serve --open --port 4205
ng build
```

## Integration
Configure the Banking Shell federation manifest to reference the generated remote entry on port `4205`, and expose/load the module according to the generated Native Federation configuration. Validate the remote independently before loading it through the host.

## Data and safety
All customer names, transactions, alerts, risk values and case records are synthetic. Case actions and rule toggles update local in-memory state only. No payment is blocked, no account is changed and no real fraud decision is made by this demo.
