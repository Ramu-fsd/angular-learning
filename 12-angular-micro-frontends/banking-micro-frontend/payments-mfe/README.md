## Business scenario

The Payments domain team owns payment initiation and operations independently from the banking platform shell. This remote demonstrates a payment workbench with a payment queue, status and priority filters, payment detail, lifecycle actions, and an initiation form using synthetic in-memory data.

## Features

- Payment operations dashboard with volume and status metrics
- Payment queue with search and filters
- Payment detail view with amount, currency, source, beneficiary, reference, and audit timeline
- Initiate a payment using reactive forms
- Simulated maker-checker workflow: submitted payments enter Pending Approval
- Approve or reject pending payments in the local demonstration
- Update payment status and add an operations note
- Angular standalone components, typed domain models, Signals, and Router

## Create the remote workspace

From the parent folder:

```bash
ng new payments-mfe --standalone --routing --style=css
```

Replace the generated `src` folder with this package's `src` folder. Copy `README.md` and `docs` into the project root.

Then:

```bash
npm install
```

## Configure Native Federation

For Angular 20/21, use the v4 bridge package:

```bash
ng add @angular-architects/native-federation-v4
```

Choose **remote**, use remote name `payments`, and port `4202`. Keep the generated federation configuration and review it. Do not replace it with older Webpack Module Federation examples.

## Run and build

```bash
ng serve --open --port 4202
```

```bash
ng build
```

## Integration with Banking Shell

The Banking Shell from Project 1 is the dynamic host. After initializing this remote, register its actual remote entry URL in the host's generated federation manifest/configuration and load the exposed remote using the helper/API generated by the Native Federation schematic. Inspect generated filenames and exposed identifiers; do not guess them.

Run this remote standalone and validate its workflows before host integration.

## Data note

All payments, parties, references, and activity are synthetic. This project is not connected to a payment rail, bank, or ledger.
